The upload target passed both mock primary/secondary backend regression and a local two-backend strict smoke, but this session did not provision or smoke-test an actual shared storage service. S3/object storage remains unimplemented.
- Full provider live smoke passed locally with real configured provider credentials and no selected-target `SKIP`. This is still a local release gate, not proof of the final deployed environment; staging/production must rerun the same strict target set after deployment and DNS/origin changes.
- Smoke accounts are ordinary user rows because the current schema has no role/expiration field. Production smoke provisioning/deletion is opt-in and does not log secrets; operators must use a dedicated smoke account, inject credentials from a secret manager, rotate the password before each production run, and run `npm run smoke:user:delete` after cleanup passes.
- The chosen submission policy is root archive + manifest dry-run; this should be rechecked if the team later moves to a root git repository.
