### Controller

@Controller('auth')는 이 컨트롤러의 기본 경로를 /auth로 설정한다.

AuthController는 인증 관련 API 메서드들을 담는 컨트롤러 클래스다.

constructor에서 AuthService를 받는데,
이는 Nest가 AuthService를 생성해서 AuthController에 주입해주는 의존성 주입이다.

@Post('email-verification/request')는
POST /auth/email-verification/request 요청이 오면
requestEmailVerification 메서드를 실행하라는 뜻이다.

@Body() dto는 요청 body를 꺼내 dto 변수에 담는다.

dto의 타입은 RequestEmailVerificationDto이고,
ValidationPipe가 켜져 있다면 DTO에 정의된 검증 규칙을 통과해야 한다.

검증이 통과하면 Controller는 dto를 AuthService의 requestEmailVerification 메서드로 넘긴다.

### Service

Service에서 처리한 결과를 Controller가 그대로 return하고,
Nest는 그 return 값을 HTTP 응답으로 클라이언트에게 보낸다.

interface는 TypeScript에서 객체의 구조를 정의하는 타입 문법이다.
EmailVerification은 인증코드와 만료시간을 가진 객체 구조를 의미한다.

@Injectable()은 이 클래스가 Nest의 DI 시스템에서 주입 가능한 provider임을 표시하는 데코레이터다.

emailVerifications는 Map을 이용한 임시 메모리 저장소다.
key는 email 문자열이고, value는 EmailVerification 형태의 인증 정보다.

private는 AuthService 클래스 내부에서만 접근 가능하다는 뜻이다.
readonly는 이 Map 변수 자체를 다른 값으로 바꾸지 못하게 한다.

requestEmailVerification과 confirmEmailVerification은 Controller에서 호출하는 Service 메서드다.

단, Service에서 dto를 받을 때 DTO 검증이 다시 일어나는 것은 아니다.
검증은 Controller 진입 전 ValidationPipe가 DTO 데코레이터를 보고 처리한다.
Service에서는 검증이 끝난 dto라고 보고 비즈니스 로직을 수행한다.
