React + ts 선택

처음에는 src 외부에 있는 파일은 신경쓰지 않아도 됨.

React 애플리케이션은 `index.html`에 정의된 하나의 root 요소에 React 앱을 마운트하고, `main.jsx` 같은 진입 파일을 통해 화면을 렌더링한다. 이러한 방식처럼 하나의 HTML 문서 안에서 여러 화면을 전환하는 구조를 SPA(Single Page Application)라고 한다.

React에서 화면 전환이 빠르게 느껴지는 이유는 SPA 구조 덕분이다. 처음 접속할 때 브라우저는 애플리케이션 실행에 필요한 HTML, JavaScript, CSS를 로드하고, 이후 화면 이동 시에는 서버에서 새로운 HTML 문서를 다시 받아오지 않는다. 대신 클라이언트에서 URL 변경을 감지하고 필요한 컴포넌트만 교체해 화면을 다시 그린다.

이 때문에 페이지 전체가 새로고침되지 않아 화면 전환이 빠르고 자연스럽게 느껴진다.

다만 SPA는 초기 접속 시 JavaScript 번들 등 필요한 리소스를 먼저 로드해야 하므로 첫 로딩 속도가 느려질 수 있다. 따라서 실제 서비스에서는 코드 스플리팅, Lazy Loading, 캐싱, 번들 최적화 같은 성능 최적화 기법이 필요하다.

코드 스플리팅은 애플리케이션 코드를 여러 번들로 나누어 필요한 화면의 코드만 로드하는 방식이다. Lazy Loading은 페이지, 컴포넌트, 이미지처럼 당장 필요하지 않은 리소스의 로딩 시점을 뒤로 미루는 방식이다. 캐싱은 한 번 받아온 정적 파일이나 API 응답 데이터를 재사용하여 중복 요청을 줄이는 방법이다. 번들 최적화는 사용하지 않는 코드 제거, Tree Shaking, Minification, 압축 등을 통해 브라우저가 다운로드해야 하는 파일 크기를 줄이는 작업이다.

이러한 최적화를 통해 SPA의 장점인 빠른 화면 전환은 유지하면서도 초기 로딩 속도와 전체 사용자 경험을 개선할 수 있다.

StrictMode는 개발 환경에서만 추가 동작을 한다.


index.css
= 앱 전체에 기본으로 깔리는 스타일을 모아두는 곳
= body, html, :root, reset, font, color 변수

App.css
= App 컴포넌트가 실제로 렌더링하는 요소들의 스타일을 모아두는 곳
= .hero, .counter, #center, #next-steps

처음 디자인 패턴은 src -> assets(img), components(개별 UI), pages(각 페이지), styles(css) 이며 css를 사용할 때 주의할 점은
css 파일을 별도로 분리해도 이름이 같으면 여러군데에 적용이 될 수 있다. 따라서 css 클래스를 선언할 때 해당 파일 이름을 앞에 붙여서 사용하는것이 좋다

## 초기 디자인 패턴

처음 디자인 패턴은 `src` 내부를 다음과 같이 구성한다.

src/
  assets/      이미지 등 정적 리소스
  components/  개별 UI 컴포넌트
  pages/       페이지 단위 컴포넌트
  styles/      CSS 파일

CSS 사용 시 주의할 점
CSS 파일을 여러 개로 분리하더라도 일반 CSS는 전역으로 적용된다.
따라서 서로 다른 파일에 같은 클래스명이나 id명이 있으면 의도하지 않은 곳에도 스타일이 적용될 수 있다.

이를 방지하기 위해 클래스명을 선언할 때는 해당 컴포넌트나 페이지 이름을 접두사로 붙이는 것이 좋다.

예를 들어 Header.css에서는 다음과 같이 작성한다.
.header-title { ... }
.header-button { ... }

HomePage.css에서는 다음과 같이 작성한다.
.home-page-title { ... }
.home-page-section { ... }
